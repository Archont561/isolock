## Purpose

Make the 0.1 release claims match what a clean user can install, configure, and successfully
use. This is a release-confidence and testability milestone, not a request to expand the
product into a registry dependency solver. Prove the advertised end-to-end journeys using
release-shaped artifacts and an explicitly selected platform/ecosystem matrix.

## Exit criteria

- [x] Publish a reviewed 0.1 support contract covering host platforms, install artifacts,
  toolchain/runtime requirements, supported workflows, and known exclusions. No platform
  or workflow is claimed without a passing acceptance job.
- [x] For every advertised ecosystem/workflow, execute clean-room CLI acceptance against
  deterministic local fixtures: consume supported lock/review inputs, acquire and verify
  bytes, then disable upstream access and prove cold offline restoration/use, integrity
  rejection, and stale-plan/drift behavior.
- [x] Install and smoke-test the actual release-shaped artifact on native runners for each
  claimed platform and installation route; verify archive/package integrity and checksums.
- [x] Exercise reviewed publication, selected-profile restoration, and the supported epoch
  policy journey with real CLI/disposable remotes and cold consumers; verify producer
  checkout/index invariants and failure/retry behavior.
- [x] Require the agreed acceptance suite for release and rehearse the candidate release
  workflow without unintended publication.
- [ ] Complete the final GO/NO-GO review against the exact merged `main` candidate SHA.
  The support contract and reproducible checklist are published; pre-merge evidence and a
  HOLD decision for the current branch candidate are recorded in
  [the release checklist](../../docs/content/docs/release-checklist.mdx).

## Scope boundaries

Keep registry solving/version selection separate unless the 0.1 scope review explicitly
adds it; reviewed manifests and lock-driven inputs remain the product boundary. Routine CI
uses hermetic fixtures, not public registry availability. This milestone does not promise
automatic legacy/sharded storage conversion, archived-epoch retirement, selective network
transport, or native publication to real project storage.
